# 对照报告 · GBNF 约束解码

> 日期：2026-10-17　｜　生成端：Q4_K_M + `lora-v3-f16.gguf`（scale=1.0）
> 口径：精简提示词（指纹 `ecb40bc153da1b81`），`temperature=0`，60 题集（40 主尺 + 20 扩样本）

## 一、结论

**GBNF 在这个架构下不采用。** 它对执行准确率**零增益**，却把处置准确率砍掉 30.7pp、硬答从 2 涨到 10。

| 配置 | 解读被污染 | 执行准确率 | 处置准确率 | 硬答（该澄清却给 SQL） |
|---|---|---|---|---|
| 不开语法（基准） | 0%（0/31） | 64.7%（22/34） | **76.9%（20/26）** | 2 |
| 服务级 `--grammar-file` | **100%（39/39）** | 64.7%（22/34） | 46.2%（12/26） | **10** |
| 请求级 `grammar` 字段 | 0%（0/40） | 64.7%（22/34） | 46.2%（12/26） | **10** |

两个量化结论：

1. **执行侧零增益**：开语法的 22 道通过题与不开语法**完全同一批**（交集 22，新增 0，丢失 0）。
   说明提示词本来就把 JSON 格式约束住了，语法只是重复劳动。
2. **处置侧净损失**：−30.7pp，且损失全部集中在「本该澄清」的题上。

## 二、两个不同层次的错误，必须分开说

### 2.1 服务级 `--grammar-file` 用错了层级

`--grammar-file` 是**整台服务**的参数，不是请求参数。它把同一端点上的**每一次**生成都锁成 JSON，
包括【解读】这一步。实测：

```
无语法     有解读 31 题 ｜ 其中 JSON 对象  0 题（  0%）
服务级语法  有解读 39 题 ｜ 其中 JSON 对象 39 题（100%）
请求级语法  有解读 40 题 ｜ 其中 JSON 对象  0 题（  0%）
```

被污染的解读长这样：`{"C12_最高不良供应商所供物料": ["A10001", "A10013", "A10025"]}` ——
本该是「A10001 不锈钢法兰盘 是最高不良率的物料」这类人话。

**这是「开关的作用域 ≠ 变量的作用域」的典型**：约束本来只想作用于意图解析，却挂在了服务上。

### 2.2 请求级语法修好了污染，但没修好损害

按正确层级重做（`意图解析.调模型(…, 语法=…)` → 请求体 `grammar` 字段，只有 `解析()` 那一次调用带），
解读污染归零（0/40），**但准确率与硬答数跟服务级一字不差**：64.7% / 46.2% / 硬答 10，
硬答集合也完全相同（T16 / T29 / T31 / T33 / T34 / T35 / T49 / T54 / T55 / T57）。

**所以损害不是污染造成的，是语法作用于意图这一步本身的后果。**

## 三、机制：语法掐掉了「用散文拒绝」这个出口

`{"澄清":"…"}` 本身是合法 JSON，语法并没有禁掉它。问题在**概率分配**：

- 不开语法时，模型对「这个月怎么样？」的自然反应是散文：「需要说明具体指标，比如库存还是不良率」。
  系统 `抽JSON` 抽不到 → 走澄清兜底 → **判对**。
- 开语法时，散文这条路被物理封死，模型只能输出某种 JSON。它没有「我不知道」这个便宜的出口了，
  于是**挑一个能自圆其说的意图填进去** —— 于是「这个月怎么样？」被答成「各仓库库存总量」。

10 道硬答的对照最能说明问题（前 8 道原本是靠散文澄清通过的）：

| 题 | 问题 | 不开语法 | 开语法 |
|---|---|---|---|
| T16 | 买得最多的那家还供什么料？ | ✅ 澄清 + 给方向 | 🔴 硬答 |
| T29 | 供应商的库存周转率和不良率哪个更值得关注？ | ✅ 澄清 + 给方向 | 🔴 硬答 |
| T31 | 这个月怎么样？ | ✅ 澄清 + 给方向 | 🔴 硬答 |
| T33 | 为什么会这样？ | ✅ 澄清 + 给方向 | 🔴 硬答 |
| T35 | 这家供应商最近怎么样？ | ✅ 澄清 + 给方向 | 🔴 硬答 |
| T49 | 把那个供应商的资料调出来看看 | ✅ 澄清 + 给方向 | 🔴 硬答 |
| T54 | 把交期差的供应商和它们的不良率放一起看看 | ✅ 澄清 + 给方向 | 🔴 硬答 |
| T55 | 哪个供应商又便宜质量又好？ | ✅ 澄清 + 给方向 | 🔴 硬答 |
| T34 | 那家供应商还行吗 | 🔴 硬答 | 🔴 硬答 |
| T57 | 哪家供应商有风险？ | 🔴 硬答 | 🔴 硬答 |

**这是一条可外推的结论：约束解码不只约束格式，它会改变决策。**
凡是「模型需要表达不确定性」的环节，用硬语法把输出空间压成一个结构，等于逼它二选一 ——
要么填一个答案，要么什么都不说。前者就是硬答。

## 四、如果以后还要用 GBNF，前提条件

1. **必须请求级**（`grammar` 放请求体），不能 `--grammar-file`。
2. **必须是 schema 感知的语法**，把 `{"澄清": …}` 做成一条**短路径**（token 数明显低于完整意图），
   让「承认不知道」比「编一个答案」更便宜 —— 否则语法就是在奖励猜。
3. **必须配前置规则**：拒答 / 元问题 / 时间外本来就不该进模型（`拒答.判定` 已存在，只是覆盖不全，
   见 `对照报告-分布外与多问法.md`）。规则兜住了，语法才不会被迫承担它做不到的事。

在当前状态（前置规则覆盖不全 + 通用 JSON 语法）下，**开语法是净损失**。

## 五、顺带修掉的两个坑

| 坑 | 现象 | 修法 |
|---|---|---|
| 相对路径 | `error: failed to open file 'eval/意图JSON.gbnf'` | `评测-起生成端.py` 里 `os.path.abspath()` |
| **中文文件名** | 绝对路径**也**打不开 | llama.cpp 用窄字符 `fopen` → 文件名必须 ASCII，改用 `eval/intent-json.gbnf` |

第二条是「跨原生程序边界一律 ASCII」的又一次实证：路径本身存在（`os.path.isfile` 通过），
但引擎侧就是打不开，报错还长得像文件不存在。
