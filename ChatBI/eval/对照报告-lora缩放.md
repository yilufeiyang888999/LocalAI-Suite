# 作品三 · #203 `--lora-scaled` 同进程对照报告

> 2026-10-17 ｜ 引擎：`llama-server-cuda.exe` ｜ 模型：`base-Q4_K_M.gguf` + `lora-v3-f16.gguf`
> 题集：`问数盲测集-60题.json`（40 主尺 + 20 扩样本）｜ 提示词：精简（`ecb40bc1`）
> 产物：`盲测结果-60题-{scale0,scale1}-同进程.json`

## 一、为什么必须「同进程改 scale」

如果按「重启换 `--lora-scaled`」做对照，两次之间会**同时**混进三种变化：

1. 权重重新加载（GGUF 解析、mmap、量化反量化）
2. 显存重新分配（KV 池位置变了）
3. 采样器 / 槽位重建

到时看到差异，分不清是 scale 造成的还是重载造成的。`POST /lora-adapters` 允许在**同一进程、同一份已加载权重**上只改一个浮点数，这是唯一能把 scale 单独隔离出来的做法。

```
GET  /lora-adapters → [{"id":0,"path":"...lora-v3-f16.gguf","scale":1.0}]
POST /lora-adapters  [{"id":0,"scale":0.0}] → {"success":true}
GET  /lora-adapters → [{"id":0,...,"scale":0.0}]   ← 必须回读，200 不算成功
```

## 二、三组比对（全部逐题，字段 = 意图 / 类型 / SQL / 解读 / 结果 / 分类）

| # | 甲 | 乙 | 结果 | 说明 |
|---|---|---|---|---|
| ① | scale=1（同进程） | 臂B：`--lora` 直挂（**另进程**） | ✅ **60 题逐题一致** | `--lora-scaled 1.0` ≡ `--lora`；且**跨进程可复现** |
| ② | scale=0（同进程） | 臂A：`--无adapter`（**另进程**） | ✅ **60 题逐题一致** | **scale=0 精确等于不挂 adapter** |
| ③ | scale=0（同进程） | scale=1（同进程） | 🔴 大面积不一致 | 判据有分辨力；scale 确实改变每一题 |

### 结论一：scale 的语义是干净的

- **scale=0 不是「挂了一个 0 权重的 adapter」，而是「等价于没有 adapter」** —— 连逐题文本都一样。
  这一点不能想当然（乘 0 仍可能改变浮点归约路径），是实测出来的。
- **scale=1 与 `--lora` 完全等价**，两条挂载路径（`--lora` / `--lora-scaled X:1.0`）可以互换。

### 结论二：跨进程同配置完全可复现

① 和 ② 都是**两个不同进程**（不同 PID、不同启动时刻、显存布局不同）跑出来的结果，却 60 题逐字一致。
结合 #201 的结论（串行 20 题两遍逐字一致），可以说：**该引擎在「串行 + parallel=1 + 温度 0」下，跨进程输出逐字可复现**。
这条比「同一进程跑两遍一致」强得多 —— 它排除了「进程内残留状态」这个解释。

### 结论三：只改 scale，业务指标 +44.1pp

| 指标 | scale=0 | scale=1 | 变化 |
|---|---|---|---|
| 执行准确率（结果集，n=34） | 7/34 = **20.6%** | 22/34 = **64.7%** | **+44.1pp（+15 题）** |
| 处置准确率（n=26） | 20/26 = 76.9% | 20/26 = 76.9% | 0.0pp |
| 安全澄清 | 4 | 1 | −3 |
| 硬答（该澄清却给 SQL） | 2 | 2 | 0 |
| 平均耗时 | 6.0 s/题 | 1.6 s/题 | **−73%** |

两点值得单独记：

- **处置准确率一模一样（20/26）** —— 说明 adapter 学到的是「怎么把问题翻译成 SQL」，不是「什么该拒答」。处置判断由规则层（拒答词表、跨指标前置、时间/实体校验）承担，这部分**微调既不改善也不破坏**。这与「能规则化的别塞提示词」一致。
- **耗时降 73%** —— adapter 让输出收敛（直接给 JSON），裸基座会输出长段思维链。这在 8G 卡上是实打实的容量收益。

## 三、判据纪律（本轮踩到的）

1. **`POST` 返回 `{"success":true}` 不能当生效** —— 必须 `GET` 回读看到 `scale=0.0`。脚本已固化：回读值 ≠ 目标值就退 1。
2. **`/lora-adapters` 取不到（None）与「空列表」必须分开**：None = 未查（退 3），空列表 = 引擎明确说没有 adapter。把 None 当「没挂」会把「没查到」写成「已确认没有」。
3. **起服务用了 `&` 后台 → Bash 返回即回收整棵进程树**，服务只活 25 秒。必须用「后台任务」方式起（本轮已踩，已改正）。

## 四、诚实标注

1. 只测了 **0 与 1 两个端点**，未测 0.5 等中间值 —— 「scale 是否线性」未验证。
2. 「scale=0 ≡ 无 adapter」只在 **Q4_K_M + 该 adapter + 该引擎版本**上验证，不可外推到其他量化档或引擎版本。
3. 未查清 scale=0 时引擎是「跳过 adapter 计算」还是「算了乘 0」—— 现象等价，机理未查明。
