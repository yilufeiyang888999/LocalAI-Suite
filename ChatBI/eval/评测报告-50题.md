### 失败题的实测 SQL

**A04** 库存低于安全库存的物料有哪些？

```sql
SELECT m.物料编码 AS 物料编码, m.物料名称 AS 物料名称, m.物料类别 AS 物料类别, ROUND(SUM(k.库存数量), 0) AS 库存合计, m.安全库存 AS 安全库存, ROUND(SUM(k.库存数量) * 100.0 / m.安全库存, 1) AS 水位百分比
FROM 库存 k
JOIN 物料 m ON m.物料编码 = k.物料编码
GROUP BY m.物料编码, m.物料名称, m.物料类别, m.安全库存
HAVING SUM(k.库存数量) < m.安全库存
ORDER BY 水位百分比 ASC
```

## 六、判据与边界（诚实标注）

1. **列超集容忍**：实测列是基准列的超集即算对（投影到基准列比对）。列名与语义层渲染一致 —— 列名是定义里的稳定契约。
2. **拒答率与误拒率分开**：混在一起会把两种相反的错抵销掉。
3. **分母固定**：不可执行题不从分母剔除。
4. **单指标覆盖缺口**：本集只覆盖语义层已定义的 5 指标 + 基础查询 + 3 场景。以下类型**本次测不到**，不是通过：① 聚合后过滤只对库存水位开放（「不良率超过 X% 的供应商」这类问法**渲染不出来**，属能力缺口）；② 双指标同表对比（不良率与采购金额并列）不支持；③ 跨表任意关联（模型不能自选 JOIN）。
5. **每档 10~15 题，分辨力约 ±7~10 pp**（1 题 ≈ 6.7~10 pp）；单看一两题的差异不构成结论。
6. **生成端提示缓存会翻答案**（本轮已控住）：同一句「这个月怎么样？」同一个提示词，`cache_prompt` 默认时得到 `{"指标":"来料不良率"}`（0.5 s），`cache_prompt=false` 时得到 `{"澄清":"需要明确具体指标…"}`（2.0 s）——开缓存时复用多少前缀取决于**上一条请求**，预填充批组成随之变化，浮点路径不同 → 近 tie 的 token 翻分支。**本报告的正式数字在 `CHATBI_NO_PROMPT_CACHE=1` 下测得**（可复现）；同题在缓存开启下重跑，**50/50 逐题结果完全一致**，只是平均模型用时 1.37 s → 2.28 s。隔离实验见 `scripts/诊断-生成端可复现.py`。⚠️ 这也说明**生产默认（缓存开）在同一句话上不保证稳定** —— 属已知边界。
