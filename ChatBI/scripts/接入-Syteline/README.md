## 依赖与主服务不同

ChatBI 主服务是「零第三方依赖，只用标准库 + sqlite3」。**本目录不属于那条线**：

- 连 SQL Server 必须 `pyodbc`（`pip install pyodbc`）
- 必须装 **Microsoft ODBC Driver 18 for SQL Server**，老的 `"SQL Server"` 驱动是 2000 年那版，
  连新版 SQL Server 会栽在 TLS 握手，且报错指向不明
- `ChatBI/scripts/` 下其它脚本**不要 import 本目录的文件**

将来真要把 SQL Server 接进服务（阶段 3），再统一决定依赖边界，别在摸表阶段就动摇主架构。

## 三步跑通

**用 ChatBI 主服务那一个解释器**（`Python314`），不要另起一个 —— 「装在这边、跑在那边」
是这个项目里已经踩过的坑，两套 Python 只会让排查多一层。

```bash
# 0. 一次性的依赖（已完成，换机器才需要重做）
P="C:/Users/Ivan/AppData/Local/Programs/Python/Python314/python.exe"
"$P" -m pip install pyodbc

# 1. 不知道库名 —— 先列库（默认连 master）
set SYTELINE_PWD=你的密码
"$P" 摸表-Syteline.py --主机 <虚机IP> --用户 sa

# 2. 选定库再摸（用只读账号，别用 sa）
"$P" 摸表-Syteline.py --主机 <虚机IP> --用户 chatbi_ro --库 <库名>

# 3. 验一遍「它真的只能读」—— 别只凭账号名信
"$P" 验-只读账号.py --主机 <虚机IP> --用户 chatbi_ro --库 <库名>
#    退出码 0=只读可用 / 1=权限不对 / 2=连不上或环境缺失

# 4. 看产出
#    out/表清单.csv / 视图清单.csv / 列清单.csv / 约束清单.csv / 摸表结果.json
```

`验-只读账号.py` 的写探针是 `UPDATE ... WHERE 1 = 0` + `ROLLBACK`，一个字节都不改，
但 SQL Server 在编译阶段就检查权限，所以能问出真实的权限边界。
**别用 `readonly=True` 去证权限** —— 那是客户端自觉，测的是 pyodbc 不是账号。

密码优先走环境变量 `SYTELINE_PWD`，其次交互输入；`--密码` 明文会留在命令历史里，不建议。

## 产出怎么用

1. **`表清单.csv` 按行数降序** —— ⚠️ **但 Top 10 里绝大多数不是业务表**。实测 `Demo` 库前 8 名
   全是 Syteline 应用框架的元数据表（`ActiveXScriptLines`、`FormComponents01/02`、`ObjProperties`
   等），业务表只有 `ledger_mst`。**按行数排序在 Syteline 上没有参考价值**，要按命名规范找：
   `_mst`（主档）、`_log_mst`（历史）、`_all`（汇总视图）。
2. **`含 site_ref 的表数`** —— 这个数字就是「问数时必须显式加站点过滤」的表数量。少了这一步，
   多个站点的数据会被加在一起，销售额凭空翻倍。实测 1,765 张（占 61.6%）。
3. **`外键数` 在新版里不为零** —— ⚠️ 这一条我原先写反了。旧版 Syteline 确实不建物理外键，
   但 **2026 版实测有 1,883 个 FK**，表间关系可以直接从 `约束清单.csv` 读，不必全靠手写。
4. **`候选业务表`** 是按表名关键词做的启发式归组，只用来快速定位，**不是判据**，需人工确认。
5. **`视图清单.csv`** —— 2,435 个视图，其中 Syteline 自带的扁平化视图（`artran_open`、
   `arinv_item`、`itemvend`）已经把主档和明细 JOIN 好，比手写多表 JOIN 稳。但 `ido` 架构只有
   30 个对象且全是框架元数据，**不是业务 IDO**；`Z*` / `AU_` / `CLM_` 前缀是 ISV 定制，别默认可用。

## 已知坑

- **Default Switch 的 IP 会变**：虚机重启后 DHCP 可能分到别的地址。IP 变了改命令参数即可，
  长期方案是换 Internal/External Switch + 静态 IP，但**别和跑通验证同时做**（一次只改一件事）。
- **行数是近似值**：取自 `sys.partitions` 元数据，不是 `COUNT(*)`。摸表只需要量级，
  Syteline 交易表动辄百万行，`COUNT(*)` 会把 IO 打满。
- **只读**：脚本不执行任何写语句、不建临时表。但连接本身用 `readonly=True`，
  真正防误写的是**账号权限**（只给 `db_datareader`），见 `阶段0-环境清单.md`。
- **SQL 里不能写中文字符串字面量**：`SELECT '表' AS 类型` 经 ODBC 到服务端会变成 `'?'`
  （单字节字符集转换），Python 侧再比对 `== "表"` 恒为假 —— 结果是「0 张表」却退出码 0。
  **类型标记一律用 ASCII（`T`/`V`），中文只在 Python 侧映射。**
- **行数不能和 `allocation_units` 一起 SUM**：一个 partition 可能对应多个 allocation_unit
  （IN_ROW_DATA / LOB_DATA），JOIN 后笛卡尔放大，`SUM(p.rows)` 虚高（实测 147 万算成 231 万）。
  行数与页数必须拆成两个子查询。
- **表与视图的口径要一致**：只查 `USER_TABLE` 而列查询覆盖「表+视图」，会让 2,435 个视图
  全部掉进差集，误报成「权限缺失」。
