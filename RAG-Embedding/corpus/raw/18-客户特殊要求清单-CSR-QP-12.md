## 1. 目的

汇总各客户的**特殊要求**（Customer Specific Requirements，CSR），明确其与本公司通用文件的**对应关系与优先级**，确保客户要求被识别、传递并落实。

## 2. 适用范围

适用于本公司**全部量产客户**。样品阶段的要求见各《样品协议》。

## 3. 优先级原则

3.1 当客户要求与本公司的通用文件**不一致**时，按以下优先级执行：

```
法律法规  >  客户特殊要求  >  本公司程序文件（QP）  >  本公司作业文件（QW）
```

3.2 客户要求**低于**本公司标准的，**不得降低本公司标准**（除非客户书面确认，且不违反法规）。

3.3 客户要求**无法满足**的，由销售部与客户协商，**不得擅自承诺**。

3.4 客户要求须**书面**（合同、技术协议、邮件确认）方为有效，口头要求不作为依据。

## 5. 特殊要求的传递与落实

### 5.1 传递路径

```
客户要求（合同 / 邮件）
      │
      ▼
销售部接收 → 填写《客户要求登记表》(QR-XS-12-01)
      │
      ▼
品质部评估 ──→ 能否满足？
      │              │
      │              ├─ 能 → 更新本 CSR 清单 + 必要时修改体系文件
      │              └─ 不能 → 销售部与客户协商
      ▼
相关部门执行（采购 / 生产 / 工艺 / 仓储）
      │
      ▼
内部审核时检查落实情况
```

### 5.2 落实检查

5.2.1 **每次内部审核**须抽查至少 2 个客户的要求落实情况。

5.2.2 客户要求**新增或变更**时，品质部须在 **5 个工作日内**完成评估与清单更新。

5.2.3 因客户要求导致的**体系文件修改**，按 **QP-01 §6** 走修订流程。

### 5.3 常见落实缺口（内审重点关注）

| 缺口 | 表现 |
|---|---|
| 要求停留在合同，未转化为作业要求 | 现场作业仍按通用标准执行 |
| 传递到品质部，未传递到车间 | 操作者不知道客户有特殊要求 |
| 客户收紧的项目（如「不得让步接收」）仍按本公司通用规则执行 | 出现违规让步 |
| 客户要求文件换版后未培训 | 相关人员仍按旧要求作业（见 QP-11 §5.2.1） |
