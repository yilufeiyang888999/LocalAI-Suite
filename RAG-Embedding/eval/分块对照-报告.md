### 0.1 本轮顺手修掉的两条判据缺陷（🔴 方法论，比数字重要）

1. **唯一事实来源。** 原脚本第 64 行硬编码了一份 33 题 `查询集`，而 `eval/题目.json` 里另有一份。
   两份漂移的风险太实在（"改了 json、脚本跑的是硬编码"）。现已把 **`eval/题目.json` 定为唯一来源**，
   所有脚本一律 `读查询集()` 从 json 读，脚本内不再存题目。
2. **分母必须固定。** 表 1 的整体 R@1 原先用 `有效 = [非 None 的题]` 做分母 ——
   等于把「结构性不可召回」的题**从分母里剔除**。这违反判据铁律：不可召回是**该方案自己的边界策略**造成的失分，
   不能通过"不算它"来美化。后果是实打实的：修前 S11 显示 **0.7458**（= 44/59），
   修后 **0.7333**（= 44/60），且修前各方案分母不一致、**行与行之间不可比**。

### 0.2 向量服务换了，16 方案全部重建（🔴 第三个判据缺陷：一个未受控变量）

**现象**：交叉护栏要求「新跑与旧跑逐题一致」，但 P01、以及 C 通道总差 1 题。
第一反应是「浮点归约误差、1 题属噪声」→ 打算把容差放宽。**没放过。**

**根因（查现场查出来的）**：起向量服务时是**多槽（slot 0 / slot 1）并行**，且服务**按最长公共前缀（LCP）复用槽位**
（服务端日志原文 `selected slot by LCP similarity`）。同一段文本在不同请求里可能落到不同槽、带不同缓存前缀，
CLS 池化输出差在 **1e-3** 量级，且**同一批连打两次都可能不同 —— 这是竞态，不是确定误差**。

`scripts/诊断-向量可复现性.py` 实测：

| 服务 | 同进程连打两次最大分量差 | 跨进程指纹 | 批量 vs 逐条 |
|---|---|---|---|
| 8081 多槽（`--parallel 2`） | **2.282e-03**（时有时无） | 不一致 | 6/8 不一致 |
| **8082 单槽（`--parallel 1`）** | **0.000e+00** | 完全一致 | 8/8 一致 |

1e-3 的抖动本身很小，但它**恰好落在「近似并列处决定名次」的量级上** —— 而 60 题下 1 题 = 1.7pp。
**处理：默认向量服务切 8082 单槽，分块 / 混合检索 / RRF 改良 / 重排 / 忠实度五组实验全部重建。**

**代价（必须诚实记录）**：主结论**方向全部保持**（§〇 五行、§一 三条），但有两处**二级结论翻转**：

1. **§六「定长-1200 在长文档子集上是全场最差（0.5909）」不成立。** 8082 下它是 **0.6818**，
   与定长-700 持平；全场最差变成定长-350（0.6364）。→ 「上限提到 1200 对定长族是负收益」这条推论**撤回**。
2. **§三 表 2「表格类并列最高（S07/S08/S13 都是 0.95）」不成立。** 重建后只有 **S08** 是 0.95，
   S07 / S13 掉到 **0.90（18/20）** —— 「强制表保在 350 上限下拿表格最高分」这个说法**恢复**。

> **教训（本项目的第 7 次同类验证）**：**「差 1 题」不能习惯性当噪声放过去。**
> 放宽容差只是**让判据闭嘴**；查清机制才发现它背后是一个**污染了整批数字的未受控变量**。
> 判据红一次就查一次 —— 红的那一格，往往就是变量泄漏的地方。

## 一、先说结论（三个问题的实验值）

| 问题 | **实验值** | 一句话依据 |
|---|---|---|
| **块大小该多大** | **上限 1200 字**（≈1.5~1.8k token），且必须配「按标题切、节内不切」 | 语料 99.7% 的自然节 ≤ 1200 字；上限从 350 提到 1200，R@1 **0.6833 → 0.7833（+10.0pp）** |
| **表格怎么切** | **不切开、但允许与前后文同块**（"软保护"） | 强制独占一块的版本被配对胜负 **8:2** 打败；逐行拆索引块数 ×3.9，且出现 1 题结构性不可召回 |
| **长文档稀释怎么破** | **少切** —— 靠结构边界，不靠重叠 | 长文档子集 R@1 0.8636（结构-1200）vs 0.6818（定长-1200）；加重叠整体 −8.3pp |

**本轮最优方案 = S07 标题-1200：R@1 0.7833、R@3 0.8833、MRR 0.8445、289 块、平均块长 271 字、表格孤儿率 0.5%、长文档子集 R@1 0.8636。**

**次优 = S13 软表保-1200：R@1 0.7667、MRR 0.8334、290 块、孤儿率 0.0%、长文档子集 R@1 0.8182。**

> 选哪个？见 §八：**生产配置仍取 S13**（孤儿率 0.0% 是硬指标，且 S07 对它的 2 胜优势只有 1 题 = 1.7pp），
> 但**必须知道 S07 现在略优**，不能再说"两者完全无差别"。

## 二、实验设计（3 × 3 因子 + 5 个对照 = 16 方案）

```
因子 A「切分方式」   定长  /  标题结构  /  标题结构 + 表格保护
因子 B「块上限」     350   /  700      /  1200
```

| 组 | 方案 | 用途 |
|---|---|---|
| S01-S04 | 定长-350 / 700 / 1200 / 700-重叠140 | 因子 A 基线 + 重叠对照 |
| S05-S07 | 标题-350 / 700 / 1200 | 因子 A 主体 |
| S08-S10 | 强制表保-350 / 700 / 1200 | 表格保护（**表格独占一块**） |
| S11 | 强制表保-700 + 表格行级索引 | 表格策略对照 |
| C01-C03 | 标题-350 / 700 / 1200 **仅文档级前缀** | **隔离变量**：边界相同，只去掉章节路径 |
| S12-S13 | 软表保-700 / 1200 | 表格"不切开但允许同块" |

族内每次只改一个变量，所以：块大小的结论在族内可比；切分方式的结论同块大小可比；
C 组把「结构边界」与「章节路径前缀」拆开算账。

### 判据（写死在脚本里的三条护栏）

1. **金标准存在性校验** —— 有一条片段在语料里找不到，脚本直接拒跑。金标准不存在时，「漏检」与「检索差」表现完全相同，那样的数字没有意义。
2. **合取匹配** —— 命中要求**同一个块**内同时含该题全部金标准片段。防"永久""观察期"这类泛词误命中。
3. **交叉护栏** —— 若某题在**全部**方案下都不可召回，脚本判定为"金标准设计可疑"并报警，不许归因于分块。

## 四、表 8 · 块上限到底在控制什么（第一个问题的答案）

| 块上限 | 节完整率 | 被切的节数 | 实得块数 | 平均块长 | R@1（标题族） |
|---|---|---|---|---|---|
| 350 字 | 76.0% | 69 | 401 | 195 字 | 0.6833 |
| 700 字 | 96.5% | 10 | 301 | 260 字 | 0.7333 |
| 1200 字 | 99.7% | 1 | 289 | 271 字 | **0.7833** |

语料共 **287 个自然节**（按 Markdown 标题切），中位数 **232 字**，均值 276 字。

**上限从 350 提到 1200（3.4 倍），平均块长只从 195 涨到 271（1.4 倍）。**
因为 96.5% 的节本来就在 700 字以内。

> ### 🔴 这是本次实验最重要的发现（扩集后更强）
> **"块大小"这个说法本身就是误导。** 在本语料上，块上限几乎不控制"块有多大"，
> 它控制的是**"要不要在语义单元中间下刀"**。
>
> 所以正确的调参动作不是"把块调到多少字合适"，而是：
> **让上限大到绝大多数自然节不需要被切** —— 在本语料上取节长的 P99 = 1200 字。
> 再往上加到 1600 只剩 0.3% 的节要救，收益已经饱和。

### 5.3 三种表格策略的正面对撞

|---|---|---|---|---|

**结论：表格要"不被切开、但允许与前后文同块"。**

三条反例都实测过：

1. **切碎**（定长-350）：孤儿率 24.5%，表格类 R@1 只有 0.65 —— 数据行还在，但**列语义丢了**，
   检索到"8 ~ 12 μm"也不知道那是"厚度要求"还是"极差"。
2. **强制表格独占一块**（S09/S10）：孤儿率降到 0%，但表格被从段落流里剥离 ——
   配对胜负 **8:2 输**给"允许同块"的版本；S09 整体 R@1 0.7000，比同上限的 S06（0.7333）低 3.3pp。
3. **逐行索引**（S11）：块数 352 → **1357（×3.9）**，R@1 反降到 0.7333（修分母后），
   且 **P07 成为结构性不可召回** —— 该题的两条证据分别落在"补测三项不达标"和"来料数据同期异常"，
   逐行拆散后**没有任何一块能同时含住两条**。**这不是"不划算"，是"这道题在该方案下永远答不出来"。**

### 5.4 为什么在 1200 上限下加不加表保"几乎无差别"

S07 与 S13 在 66 条题上 **2 胜 / 64 平 / 0 负**，块数 289 → 290、孤儿率 0.5% → 0.0%，
R@1 0.7833 → 0.7667。**胜负全部来自同一道题，属于噪声级。**
因为 1200 已高于 99.7% 的节和 98.6% 的表 —— **表格保护的价值只在"上限不足"时兑现**。
它在 350 上限下把表格类 R@1 从 0.80（S05）拉到 0.95（S08）。

> ⚠ 原报告在这里写的是"完全无差别（37 条全并列）"。**扩集后这个说法要撤回**：
> 两者确实只差 1 题，但"完全并列"是小样本造成的假象。**同一份数据、不同样本量，能给出相反的定性描述。**

4. **表格强制独占 —— 有害**（S09 0.6818，与定长-700 / 定长-1200 / 行级索引同档，只比最差的定长-350 好）。

### 6.1 隔离变量：到底有多少收益来自"标题路径"

对照方式：**边界完全相同**，只把块前缀从「文号 + 文档标题 + 章节路径」换成「文号 + 文档标题」。

| 对照 | 甲胜 | 平 | 乙胜 | R@1 变化 |
|---|---|---|---|---|
| S05 标题-350 vs C01 仅文档前缀-350 | 9 | 49 | 8 | 0.6833 → 0.6667（**无差别**） |
| S06 标题-700 vs C02 仅文档前缀-700 | 7 | 54 | 5 | 0.7333 → 0.7333（**无差别**） |
| S07 标题-1200 vs C03 仅文档前缀-1200 | 8 | 54 | 4 | 0.7833 → 0.7333（**−5.0pp**） |

另一条对照：**同为文档级前缀，只有边界逻辑不同**——

| 对照 | 甲胜 | 平 | 乙胜 | R@1 |
|---|---|---|---|---|
| S02 定长-700 vs C02 标题-700-仅文档前缀 | 12 | 44 | 10 | 0.6667 → 0.7333（**+6.7pp**） |

**所以收益的归属是清楚的：**

- **结构边界（不切断自然节）：+6.7pp** —— 这是主要来源，且在 350/700/1200 三档方向一致。
- **章节路径前缀：350/700 上 0，1200 上 +5.0pp** —— **上限越大越值钱**
  （块大时前缀是块内唯一的定位信息）。它是"锦上添花"，不是"雪中送炭"。
- **但在跨文档类上，章节路径是负收益**（C02/C03 0.43 vs S06/S07 0.29，见 §三表 2）——
  细到小节的路径会把注意力带到错误文档。**这两条并不矛盾：路径前缀帮"定位同一份文档内的位置"，害"跨文档找对文档"。**

> 这条隔离对照值得单独记一笔：如果不做 C 组，很容易把"+6.7pp"全记在"标题分块"头上，
> 从而在别的语料上做出错误外推。**收益要拆到变量级别才算数。**

## 九、复现方式

```powershell
# 1. 起向量服务（CPU 即可；-b/-ub 必须调大，否则长块会报 500；--parallel 必须为 1）
cd D:\workspace\10-LocalAI-Installer\engine\backends
.\llama-server.exe --model D:\workspace\7-AI-Code\RAG-Embedding\models\bge-m3-Q8_0.gguf `
    --embedding --pooling cls --port 8082 -b 4096 -ub 4096 --parallel 1

# 2. 跑对照实验（16 方案 × 66 题，约 100 秒）
cd D:\workspace\7-AI-Code\RAG-Embedding
python scripts\实验-分块对照.py

# 3. 追单条题在各方案下的排名
python scripts\查看-逐题明细.py --题 P01
python scripts\查看-逐题明细.py --失败

# 4. 起服务后先自检「向量是否可复现」（全绿才继续跑实验）
python scripts\诊断-向量可复现性.py 8082
```

> **坑 1（环境）**：`llama-server` 默认 `n_ubatch = 512`，**单个块的 token 数超过 512 会直接 500**，
> 报错藏在服务端日志里（`input (516 tokens) is too large to process`），客户端只看到一个 500。
> 1200 字的中文块 ≈ 1500+ token，必然触发。起服务时必须带 `-b 4096 -ub 4096`。
>
> **坑 2（判据）**：文号提取**不能枚举字号**。早期只写了「文件|表单」，
> 而技术协议用的是「**协议编号**」→ 匹配失败回退成文件名 → 那个文档所有块的前缀里的文号都是错的。
> 改成 `[^*]{0,8}编号` 通配后再核对 18 份文号才对齐。
> **教训：凡是"从文里抽字段"的代码，必须对全部样本做一次穷举核对。**
>
> **坑 3（评测集）**：见 §0.1 —— **唯一事实来源 + 分母固定**。
> 这两条都是"脚本能跑、数字漂亮、但结论是假的"的典型。
>
> **坑 4（🔴 复现性）**：`--parallel` **必须为 1**。多槽并行时服务按**最长公共前缀**复用槽位，
> 同一段文本可能落到不同槽、带不同缓存前缀 → 池化向量差 **1e-3**，且**不是确定误差，是竞态**
> （同一批连打两次都可能不同）。后果不是"精度略降"，是**结果不可复现** ——
> 近似并列处的名次会在两次运行之间漂移，而 60 题下 1 题 = 1.7pp。见 §0.2。
