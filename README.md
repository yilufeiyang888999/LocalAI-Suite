# LocalAI Suite · 本地大模型应用三件套

在**一台普通 Windows 电脑**上跑通「模型部署 → 知识库问答 → 经营数据问数」的完整链路。
全链路离线：不出网、不调云端 API，模型权重与数据都留在本机。

> 面向的场景不是「跑个 demo」，而是**让不懂模型的人也能把本地模型用起来**：
> 装完点一下就能聊、问制度能给出原文出处、问数字能落到 SQL 并留下审计记录。

<br>

## 三个模块

| 模块 | 目录 | 解决什么 | 形态 |
|---|---|---|---|
| **① 部署助手**（底座） | 本仓库根目录 | 模型怎么装、显卡够不够、该开多大上下文、后端选哪个 | Tauri 2 桌面应用（Rust + Vue 3） |
| **② 知识库问答** | `RAG-Embedding/` | 「制度怎么规定的」——检索 + 引用 + 拒答 | 本地 Python 服务 + 网页 |
| **③ 智能问数** | `ChatBI/` | 「这个月不良率多少」——自然语言 → SQL / 单据 | 本地 Python 服务 + 网页 |

三者共用同一套虚构制造企业的数据：`RAG-Embedding` 的制度文档与 `ChatBI` 的 6 张业务表互为表里，
所以「制度里写的口径」和「数据库里算出的数字」能对得上。

<br>

## 架构

```
                       ┌─────────────────────────────┐
                       │   Local-AI 桌面应用          │
                       │   模型下载 / 生命周期 / 显存规划 │
                       └──────────────┬──────────────┘
                                      │ 启动并托管
                                      ▼
                       ┌─────────────────────────────┐
                       │  llama.cpp server :8000     │  OpenAI 兼容接口
                       │  GGUF 量化模型（CUDA/Vulkan）│
                       └───────┬─────────────┬───────┘
                               │             │
                 ┌─────────────▼──┐   ┌──────▼────────────┐
                 │ 知识库 :8092   │   │ 智能问数 :8095/8096 │
                 │ 检索+重排 :8085│   │ 语义层 → SQL       │
                 │ 引用 / 拒答    │   │ 权限 / 审计 / 单据  │
                 └────────────────┘   └───────────────────┘
```

**分工原则**：桌面应用只负责「让模型活着、跑得快」；业务逻辑一律在 Python 侧，
两边用 HTTP 说话。这样换模型、换量化、换硬件都不用动业务代码，反过来也一样。

## 快速开始

### 环境

| 项 | 要求 |
|---|---|
| 系统 | Windows 10/11 x64 |
| 显卡 | NVIDIA（CUDA 后端）或其他能跑 Vulkan 的卡；纯 CPU 也能跑，只是慢 |
| 内存 | 8 GB 起；跑 7B 以上建议 16 GB |
| 工具链 | Node.js ≥ 20、Rust ≥ 1.80、Python ≥ 3.10 |

> **仓库根目录的 `index.html` 不能双击打开。**
> 它只是 Vite 的开发入口，用 `<script type="module" src="/src/main.ts">` 引入 TypeScript 源码：
> 浏览器不认 `.ts`，`file://` 协议下 ES 模块又会被 CORS 拦掉，双击只会得到一个空白页。
> 仓库里也没有 `dist/`（构建产物与 `node_modules/` 都在 `.gitignore` 里）。
> 要看界面只有两条路——装安装包，或起开发服务器（见下）。

### ① 桌面应用

```bash
npm install                # 或 npm ci（按 lock 文件精确安装）
npm run dev                # 只起前端：浏览器访问 http://127.0.0.1:1420
npm run tauri:dev          # 开发模式：前端 + Rust 后端，桌面窗口
npm run tauri:build -- --bundles nsis   # 出安装包
```

首次启动会自动检测显卡、推荐后端与量化档位，并按实际空闲显存计算能开多大上下文。
模型与引擎在应用内下载，不下进仓库。

> `npm run dev` 在浏览器里**只能看到外壳**：前端 39 个后端命令调用全部集中在 `src/api/tauri.ts`，
> 一律走 Tauri 的 `invoke`，且没有「非 Tauri 环境」的兜底 —— 挂载时的硬件检测会直接失败，
> 页面停在加载态、按钮点了报错。
> 这是预期行为，不是装坏了；要看真实功能请用安装包或 `npm run tauri:dev`。

### ② 知识库

```bash
cd RAG-Embedding
# 先把 bge-m3 / bge-reranker 的 GGUF 放进 models/（体积大，未入库）
python scripts/启动-服务.py     # 起 8085 重排 + 8092 知识库，并自检
```

浏览器打开 `http://127.0.0.1:8092/` 。

### ③ 智能问数

```bash
cd ChatBI
python scripts/启动-服务.py     # 起 8095 问数 + 8096 编排入口
```

浏览器打开 `http://127.0.0.1:8096/` 。

| 评测 | 结果 |

| 桌面应用 | `cargo test --lib` **281 项通过**（0 失败 2 忽略），`cargo check` 零警告 |

## 工程上踩过的坑（选摘）

这套东西真正的难点不在「调通」，而在**别让界面骗你**：

- **显卡显存口径**：不能拿总显存算卸载层数。用总量会算出「能全量卸载」，实际溢出到共享内存，
  表现是**启动成功但慢十倍**，且不报错。改为按空闲显存规划，并扣掉驱动基线（TCC 与 WDDM 基线不同）。
- **降档归因**：显存不够时要分清「模型太大」还是「别人占着卡」。判据用反事实——
  空卡能不能全量装下；能，现在不能，才是别人的锅。
- **停止服务**：`taskkill` 返回「已结束」只代表指令发出，socket 还要几十毫秒才拆。
  查一次端口必然误判，改成「等到让出或超预算」。
- **日志首行别说谎**：曾把配置里的 `log_level` 当生效级别打印，环境变量覆盖后首行仍写 `INFO`，
  于是所有「见到 DEBUG 行才算走到」的判断都会被读反。现在同时打设置值、生效值、来源。
- **同一事实只留一份定义**：SQLite 视图建时不校验视图体，表名写错会静默放行全量数据；
  配置与脚本各写一份阈值，改一处跑另一处不报错、只给错报告。

更多细节写在 `本地AI模型一键部署助手 开发技术文档.md`。
