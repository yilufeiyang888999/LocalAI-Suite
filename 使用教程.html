本地AI模型一键部署助手 · 使用教程

从「下载安装包」到「问出第一个问题」，全部在本机完成 —— 数据不出门，也不联网调用云端模型。

版本 0.1.7 Windows 10 / 11 64 位 Tauri + llama.cpp 无需命令行即可使用

一这个项目是什么

一句话：把「在 Windows 上跑起一个本地大模型」这件事，从一长串命令行操作，变成一个装上就能点的桌面软件。

手工部署本地模型，绕不开这几道坎：认显卡、算显存、挑量化档、去镜像站找几十 GB 的文件、编译或找对版本的推理引擎、敲一长串启动参数。任何一步错了，大概率只得到一句语焉不详的报错。这个软件把这条链路整段接管了。

它替你做了什么

手工部署这个软件
认显卡型号、查显存、估能跑多大的模型硬件体检 + 场景推荐，直接给出「这台机器能跑哪几个」和理由
去 HuggingFace / ModelScope 找 gguf 文件，几十 GB 慢慢下一键下载：自动测速选线路、断点续传、可暂停、可限速
自己编译或找对版本的 llama.cpp，配 CUDA / Vulkan自动下载匹配本机显卡的后端引擎，失败自动退到 CPU 模式
敲 llama-server 的一堆参数（层数、上下文、KV 量化）按可用显存自动算参数量，用户不用懂
自己找聊天界面接上去内置对话界面，另带企业知识库问答与智能问数
出问题只能看日志猜故障自查 + 一键修复 + 脱敏诊断日志导出

能力总览

能力说明前置条件
模型部署硬件体检 → 场景推荐 → 一键下载 → 自动起服务；支持导入已有的 .gguf 文件无
通用对话流式回答、三种角色预设（日常助手 / 文案写作 / 代码助手）、可调「严谨↔创意」、多会话管理、记录只存本机装好一个模型

桌面应用（Tauri 2 + Vue 3 + Rust）

二安装

三步：下安装包 → 选保存位置 → 双击装完。

2.1 先看这台电脑够不够

项目建议说明
系统Windows 10 / 11 64 位软件是 Windows 桌面应用
内存16 GB 以上8 GB 只能跑最小的模型
显卡NVIDIA 独立显卡（推荐）没有独显也能用，但会走 CPU 模式，回答明显变慢
磁盘至少 50 GB 空闲模型按 4 GB ~ 30 GB 一个算，另外还有推理引擎

2.2 安装包

文件名：本地AI模型一键部署助手_0.1.7_x64-setup.exe

校验项值
文件大小9,000,084 字节
SHA256（前 8 位）7654A15B
文件版本0.1.7
拿到多个同名安装包时，认指纹、别认文件名。同名文件被重新构建过时，文件名不会变，内容会变。装完后可以打开软件右侧「设置 → 关于」看版本号，应显示 0.1.7。

2.3 安装步骤

  1. 双击安装包（Windows 可能提示「未知发布者」，选「仍要运行」）。
  2. 选择安装位置，一路「下一步」到完成。
  3. 从开始菜单或桌面图标启动。

2.4 首次启动会发生什么

  • 软件自动做一次硬件体检，并准备好推理引擎（后台下载，界面上会有进度提示）。
  • Windows 可能弹窗询问是否允许运行本地服务 —— 选「仍要运行」，否则服务起不来。
  • 如果上一次用过某个模型，软件会尝试自动把它重新拉起来，不需要重新配置。

2.5 想换地方放模型

默认放在安装时选定的目录下。空间不够时，到右侧「设置」改「AI文件保存位置」，建议指到大容量磁盘（例如 D 盘）。已有的模型不会自动搬过去 —— 换目录后重新下载或重新导入即可。

三七步上手

主界面的卡片是按顺序编号的，跟着往下点就行。左侧是主流程（1→7），右侧是三个随时可用的面板。

1
硬件体检
自动识别显卡、显存、内存、CPU 核心数，判断这台电脑适合跑哪一档模型。
要做什么：看一眼结果即可。如果识别得不对（比如双显卡机器认错了），可以手动指定显存档位再重新推荐。识别不到独显通常意味着驱动没装或版本太老 —— 下面第 1 步的故障自查会给出驱动下载入口。
2
选择使用场景
四选一：日常聊天问答 / 写文案·写报告 / 写代码 / 通用。
为什么影响推荐：不同用途看重的能力不一样（中文长文表达、代码理解、通用表现），选完下面的推荐模型会跟着变。
3
推荐模型
最多列三个候选，每个都写了「为什么推荐它」。已装过的会标「已安装」，按钮变成「直接使用」。
要做什么：挑一个点「开始安装」。越大的模型越聪明，也越慢、越占显存；拿不准就先装推荐列表第一个。
4
安装进度
显示下载 → 校验文件 → 启动服务 三个阶段。下载中可以暂停 / 继续 / 取消。
默认线路：先试 ModelScope，失败自动换 hf-mirror。下载慢可以在「设置」里限速，避免把整条带宽占满。
5
聊天
装好就能问。三种模式：通用对话 / 知识库问答 / 智能问数（详见 §4）。
通用对话下还有：角色预设（日常助手 / 文案写作 / 代码助手）、「严谨 ↔ 创意」滑杆、左侧会话列表（可重命名、删除）、「清空上下文」（保留历史消息，但让 AI 忘掉之前的内容）。
6
已安装模型
所有下载过或导入过的模型都在这。可以切换当前模型、检查更新、停止服务、启动、卸载、导入本地模型。
带「微调包」角标的模型：启动时会自动挂上它自己的 LoRA 适配器并套用配套对话模板，不需要你手动配。
停止 / 启动不会丢配置：改了端口或想换模型时，先在这里停止、再启动即可。
卸载时会问一次「是否连同聊天记录一起删除」—— 取消就只删模型、保留记录。
7
在其他应用中使用本地AI
列出本机 AI 的调用地址与密钥，并给出常用客户端的填入模板，一键复制。
详见 §5。

右侧三个面板（随时可用）

面板用途
设置 / 离线导入保存位置、下载限速与线路、开机自启、AI 自称名字、谁可以调用、端口、知识库与问数服务地址；展开后还有代理、日志级别、自定义运行参数、导入本地模型、数据管理与「关于」。
故障自查点「开始检查」逐项体检（显存、运行库、模型文件、显卡驱动、磁盘空间等），能一键修的会给按钮。附「导出诊断日志（已脱敏）」。
后端一致性校验拿同一个问题分别跑两个显卡后端，比对输出是否一致 —— 用于确认「换了后端之后结果没变味」。校验期间会重启两次服务，聊天会短暂不可用。

4.1 通用对话

  • 直接在输入框提问。回答是「边想边出字」的流式输出，可以随时点「停止」打断。
  • 左上角可切换角色预设（日常助手 / 文案写作 / 代码助手），影响回答的语气与侧重。
  • 右侧滑杆：往左更严谨、往右更有创意。
  • 下方绿色框里显示的是 「其他程序调用本机AI的地址」（OpenAI 兼容），可以直接复制走。
  • 如果当前跑在「CPU 模式」，会有一条提示条和「恢复显卡加速」按钮 —— 点一下会重试显卡。

4.2 企业知识库问答

切到「知识库问答」标签后，顶部会显示服务是否连上、连的是哪个地址、库里有几份文档几块内容。

怎么把服务起起来：到作品一目录下运行它的启动器（它会一并把检索用的重排服务也带起来）：

cd "D:/workspace/7-AI-Code/RAG-Embedding"
python scripts/启动-服务.py

只想单独起知识库服务本身，也可以用 python scripts/知识库服务.py。

有一类失败不会报错，只会一直答不出来 —— 生成端端口对不上。 知识库服务内部默认去 http://127.0.0.1:8000 找生成引擎；如果本软件的「接口端口」不是这个值，提问时会一直返回「资料不足 / 生成失败」，而服务本身照常 200 响应。 软件检测到这种不一致会直接提示，按提示带上 --生成端 http://127.0.0.1:<实际端口> 重启它即可。

4.3 智能问数

一个入口，三种问题不用自己分类（路由是系统的责任）：

类型问什么看点
制度类「不合格品应该怎么处理？」给出引用出处（哪份制度、哪一节）
数据类「上月哪家供应商不良率最高？」口径说明 + 生成的 SQL + 结果表
动作类「给东莞精诚出一份质量整改通知」要看角色：权限不够会被明确拒绝，且不生成任何单据

怎么把服务起起来：到作品二目录下运行：

cd "D:/workspace/7-AI-Code/ChatBI"
python scripts/启动-服务.py

它的「知识问答」链路会转发给作品一，所以那条链路要求 8092 也开着。界面会逐条显示三条链路的可达情况，缺哪条会直接点名。

「发起角色」是干什么的：决定「能不能提交申请 / 对外发文」。切换角色再问同一个问题，就能看到权限约束的效果 —— 被拒时会告诉你需要什么角色，而不是一句「失败」。
说明：当前角色是调用方自己选的标签，用于演示权限关口与留痕；真实部署应接入统一身份认证。

4.4 想一次把全部服务起齐

三个仓库的交叉演示有一条命令（先手动启动本软件的 AI 服务，再跑它）：

cd "D:/workspace/7-AI-Code/AI大模型应用开发实战训练营/整合演示"
python 一键启动.py            # 体检 → 起缺的服务 → 全链路自证
python 一键启动.py --状态      # 只看现状，不动现场
python 一键启动.py --停        # 停掉两条支线（不动本软件的引擎）

它只按依赖顺序转交给各仓库自己的启动器，本身不拼任何服务的启动命令 —— 避免同一份配置两处定义。

五接入第三方应用

本机的 AI 服务是 OpenAI 兼容接口，任何支持「自定义 OpenAI 地址」的软件都能直接接上。

5.1 三个值

填什么值
Base URLhttp://127.0.0.1:<端口>/v1（端口以「聊天」页显示的地址为准）
API Keysk-no-key-required（本地服务不校验，随便填一个非空值也行）

软件内「在其他应用中使用本地AI」那块会按你当前的端口和模型自动算好，带一键复制按钮和每个应用的逐步说明 —— 优先照那里抄，别手打。

5.2 常用应用

应用关键动作
Cherry Studio设置 → 模型服务 → 添加 → 提供商类型选 OpenAI → 填地址 / 密钥 / 模型名
Chatbox设置 → AI 模型提供方选 OpenAI API → 把 API Host 改成上面的 Base URL
CursorSettings → Models → 填 OpenAI API Key → 打开「Override OpenAI Base URL」→ Verify
Continue.dev编辑 ~/.continue/config.yaml，软件内提供整段可复制配置
其他任何标称「OpenAI 兼容」的应用，按 §5.1 三个值填即可

可用接口：/v1/models、/v1/chat/completions、/v1/completions。

5.3 让局域网其他设备也能用

  1. 右侧「设置」→「谁可以调用本机AI」改成「局域网内其他设备也可访问」。
  2. 保存后，到「已安装模型」里停止服务再启动（端口监听方式改了，必须重启才生效）。
  3. 重启后「聊天」页会多出一条局域网地址，形如 http://192.168.x.x:<端口>/v1，在别的设备上用它。
开之前想清楚：开启后，同一局域网内任何人都能直接调用你的本机 AI，没有密码保护。只在可信网络（家庭 / 公司内网）开。

七遇到问题怎么办

顺序：先用内置的故障自查，再对着下面的表找。

7.1 内置三条路

  1. 「故障自查」→ 开始检查：逐项体检（显存、运行库、模型文件、显卡驱动、磁盘空间…），能自动修的直接给按钮。
  2. 「导出诊断日志（已脱敏）」：一键打包日志，用于反馈问题。
  3. 「后端一致性校验」：怀疑「换了显卡后端之后结果变味」时用。

7.2 常见问题对照

现象多半是什么怎么办
回答很慢，一条要等很久 跑在 CPU 模式，或模型对这台机器太大 看聊天区有没有「CPU 模式」提示条 → 点「恢复显卡加速」；仍不行就换更小的模型（回到第 3 步重新装）
启动服务时 Windows 弹窗拦截 系统防火墙 / 安全提示 选「仍要运行」；仍被拦就到 Windows 安全中心放行
下载很慢或反复失败 线路不通 「设置 → 下载线路」换成另一条；或设置里配代理；已有 gguf 文件就直接「导入本地模型」
改了口 / 改了局域网设置，没生效 端口是启动时绑定的 到「已安装模型」先停止、再启动服务
知识库问答一直「资料不足 / 生成失败」，但不报错 知识库服务内部的生成端端口和本软件当前端口不一致 看界面上的不一致提示，按它给的命令带 --生成端 重启知识库服务
「智能问数」显示部分链路不可达 「知识问答」那条依赖作品一（8092），它没起 另两条（数据问数、动作执行）照常可用；要用知识问答就去起 8092
端口在监听、进程也在，但所有请求超时 服务控制台窗口被鼠标拖选，进程的下一次输出被永久阻塞 到那个服务的窗口按一下 Esc，不用重启
日志文件找不到 文件名带日期后缀 在数据目录的 logs 文件夹里，形如 localai.log.2026-10-16（不是 localai.log）

7.3 反馈问题时要带什么

  1. 「导出诊断日志（已脱敏）」产生的 zip。
  2. 「设置 → 关于」里的版本号（例如 0.1.7）—— 同一版本号可能对应不同构建，最好连安装包指纹一起给。
  3. 你做了什么、期望什么、实际看到什么。
